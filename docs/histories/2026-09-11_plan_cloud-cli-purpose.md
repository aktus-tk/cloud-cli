## 背景

`cloud-cli`は、クラウドCLIを単に統一するためのツールではありません。主目的は以下です。

1. AI Agentが必要とする入力コンテキストと出力トークンを削減し、skillから利用しやすい安定したコマンド体系を提供する
2. 人間がよく使うCLI操作とオプションを短いコマンドにまとめ、必要な情報だけを見やすく整形して出力する
3. AI Agentとの実運用で発見した頻出操作や再利用可能な情報取得処理を継続的に取り込み、人間とAIが共同で育てる

公式CLIの全機能を再実装したり、AWS・GCP・Tencent Cloudの差異を完全に抽象化したりすることは目的としません。

## 責務境界

次の境界を明記してください。

```text
skill
  何を、どの順序で調査するかを定義する

cloud-cli
  調査に必要な情報を短く安定したコマンドで取得し、
  必要最小限に整形して出力する

公式CLI
  クラウドAPIを直接操作する
```

調査手順全体をcloud-cliへ実装しないでください。cloud-cliへ取り込むのは、複数のskillや調査から再利用できるCLI操作・情報取得処理です。

## コマンド追加基準

次の条件を複数満たす操作を追加対象としてください。

* 実運用で複数回利用している
* 公式CLIのオプションが長い、複雑、または覚えにくい
* 公式CLIの生出力が大きすぎる
* 複数のプロジェクトや調査で共通利用できる
* skillから安定して呼び出したい
* 入力または出力トークンを明確に削減できる
* 人間が日常的に使用する

一度しか使わない処理、顧客・プロジェクト固有の処理、複雑なワークフローは追加せず、公式CLIまたは各プロジェクトのskill/runbookで扱ってください。

## 実行ポリシー

READMEには次の要約だけを残してください。

* Read-only操作と通常の変更操作は直接実行する
* 破壊的・高リスクな操作は実行せず、公式CLIコマンドだけを表示する
* `--debug`では操作を実行せず、実行予定コマンドだけを表示する
* 詳細な分類基準は`AGENTS.md`を参照する

現在の表にある「コマンド出力のみ」は曖昧なので、次の表現へ統一してください。

```text

```

操作の危険性は`create`、`get`、`delete`などの名前だけで判定せず、データ損失、不可逆性、秘密情報の露出、復旧可能性、影響範囲で判断する規則をAGENTS.mdへ記載してください。
